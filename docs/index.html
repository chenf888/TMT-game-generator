How a game gets made 一个游戏是如何做出来的

Every run walks the same eight stages and nothing skips ahead. The first two are design, the middle three are code and verification, and the last two are measurement rather than estimate. 每次运行都走同样的八个阶段，绝不跳步。前两个是设计，中间三个是编码与校验，最后两个是实测而非估算。

01
Interview访谈
Seven questions lock the theme, the scale, the natural ceilings, the pacing target, the side content, and the language tier. A scorer then works out which kind of game this actually is, because that decides which components are allowed to exist at all. 七个问题锁定主题、规模、自然上限、节奏目标、支线内容和语言层级。随后一个评分器判断这究竟是什么类型的游戏，因为它决定了哪些组件被允许存在。
02
Design brief设计简报
A layer-by-layer table filled from measured blueprints and the corpus defaults, then self-checked against twenty-one rules. This stage has to pass before anyone types a line of game code. 逐层填写的表格，数据来自实测蓝图与语料库默认值，再对照二十一条规则自检。任何一行游戏代码动笔之前，这一阶段必须先通过。
03
Scaffold脚手架
A fresh TMT v2.7 folder with a permanent savefile id, patched by a bundled script that also syntax-checks what it wrote. 生成一套全新的 TMT v2.7 文件夹并写入永久存档 id，再由捆绑脚本打补丁，同时对自己写入的内容做语法检查。
04
Generate生成
Layer code that keeps every number inside a Decimal: upgrades with genuinely varied effects, milestones, challenges, buyables, automation ladders, softcaps, and the theming. 层级代码让每个数字都保持在 Decimal 之内：效果真正有差异的升级、里程碑、挑战、可购买项、自动化阶梯、软上限，以及主题化。
05
Static checks静态检查
68 rules read the source, gated by the locked game type. A FAIL blocks testing outright. A WARN has to be answered in writing in the brief, or it counts as a failure. 68 条规则阅读源码，由已锁定的游戏类型决定是否触发。FAIL 直接阻断测试。WARN 必须在简报中书面回应，否则视同失败。
05.5
Load-time smoke加载期冒烟测试
The real mod files are loaded in Node against engine stubs. Loading throws, duplicate layer ids, broken startData contracts, and hooks that return NaN are all caught here, before the browser ever opens. 真实的 mod 文件会在 Node 里对着引擎桩加载。加载抛错、层级 id 重复、startData 契约损坏、钩子返回 NaN，全部在这里被抓住，浏览器还没打开。
06
Balance平衡
A headless simulator plays the build and reports the real timeline, hour by hour. The brief's numbers are checked against that measurement instead of against arithmetic on paper. 无头模拟器实际游玩这个构建，逐小时汇报真实时间线。简报里的数字要拿它来核对，而不是拿纸面算术核对。
07
Hand off交付
You serve the folder and play it, working down a checklist for the console, the saves, the offline cap, and whether the endgame actually fires. 你启动这个文件夹来玩，按清单逐项检查控制台、存档、离线上限，以及终局是否真的触发。

The numbers come from games people already shipped 这些数字来自别人已经发布的游戏

None of the thresholds in this skill are opinion. They come from a numeric archive of every component in 329 published TMT games: 36 MB of source, parsed component by component, each figure traceable to a file and a line. 这项技能里没有一个阈值是拍脑袋定的。它们来自一份数字档案，收录了 329 款已发布 TMT 游戏的每一个组件：36 MB 源码，逐组件解析，每个数字都能追溯到某个文件的某一行。

Size and shape are two different questions 规模与形态是两个不同的问题

Scale is settled by Q2: five to seven layers, or twenty-five and up. Shape is settled separately, by counting how many of those 329 games let the player act at all, and how. That ratio is not a guess. It decides which components are mandatory, which are forbidden outright, and which checks the build has to survive. 规模由 Q2 决定：五到七层，或者二十五层以上。形态则单独决定，方法是统计那 329 款游戏里有多少让玩家真正动手，以及怎么动手。这个比例不是猜的。它决定了哪些组件是必需的、哪些被直接禁止、以及这个构建必须通过哪些检查。

Share of the 329-file corpus. The last segment is the files where no single interaction model dominates, 18.6% of the set. 占 329 份语料库的比例。最后一段是没有任何单一交互模型占主导的文件，占全集的 18.6%。

passive-prestige53.5% Accumulate and reset, never act. normal and static layers only, with no tick, no clickables and no grid. Having no tick here is correct, and the rule set exempts it rather than flagging it. 积累与重置，从不主动操作。只有 normal 和 static 层级，没有 tick、没有可点击项、没有网格。这里没有 tick 是正确的，规则集会豁免它而不是标记它。
active-click11.2% Discrete taps. Every clickable defines canClick() and onClick(), and its state lives in startData. A clickable missing its handler is a FAIL, not a headline count. 离散点击。每个可点击项都定义 canClick() 和 onClick()，其状态存放在 startData 中。缺少处理器的可点击项是 FAIL，不是一个用来充数的标题数字。
active-tick10.0% A continuous quantity the player pushes. Needs update(), bars with a real progress(), and tick-hook registration. 玩家持续推动的连续量。需要 update()、带真实 progress() 的进度条，以及 tick 钩子注册。
board-minigame6.7% The playfield is a 2D board. Grid contract: a getStartData hook, a rows and columns spec, and base-100 cell ids. 操作场是一块 2D 棋盘。网格契约：一个 getStartData 钩子、行列规格，以及百进制单元格 id。
A mechanic that needs an interaction model is gated, never quietly dropped. The score-attack challenge hub records its peak inside update(), and this engine has no score-attack API, so that pattern is hand-rolled and genuinely needs a tick. Ask for it on a passive game and the skill says so, writes the reason into the brief, and carries on. A game that declares no type at all is checked exactly the way it was checked before types existed. 需要交互模型的机制会被门控，而不会被悄悄丢掉。积分挑战中心把峰值记录在 update() 里，而这个引擎没有积分 API，所以那种模式是手写的，确实需要 tick。你在一个被动游戏里要求它，技能会直接说明，把理由写进简报，然后继续。一个完全不声明类型的游戏，检查方式与类型出现之前完全一致。

The bugs a text checker cannot see 文本检查器看不见的 bug

Three defects reached a real player before any of the 53 rules in force at the time could say a word. That rule set reported zero failures on that build, because it asks whether things are wired and how big they are, while all three bugs were about what survives a reset. 有三个缺陷到达了真实玩家手里，而当时生效的 53 条规则一声都没吭。那套规则在那个构建上报了零失败，因为它问的是东西接没接上、有多大，而这三个 bug 全都是关于重置后什么能活下来。

The engine prestiges straight out of the game loop, if (tmp[layer].autoPrestige && tmp[layer].canReset) doReset(layer), with no player toggle anywhere in that path, and resetsNothing() is the only brake. So automation a player cannot switch off has to be safe by construction. The invariant is short: what auto-prestige requires must imply what makes the reset harmless. 引擎直接从游戏循环里触发转生，if (tmp[layer].autoPrestige && tmp[layer].canReset) doReset(layer)，这条路径上没有任何玩家开关，resetsNothing() 是唯一的刹车。所以玩家关不掉的自动化，必须在构造上就是安全的。不变式很短：自动转生所需的条件，必须蕴含使重置无害的条件。
as generated生成时的样子
autoPrestige() {
  if (hasMilestone(this.layer, 2)) return true
}
resetsNothing() {
  if (hasMilestone("sg2", 3)) return true
}

Automation turns on at this layer's second milestone. The reset only stops hurting orders of magnitude later, at sg2's third. In between, the layer wipes its own supply every frame. 52 of the 98 automated layers in that game behaved this way. 自动化在这一层的第二个里程碑开启。而重置要等到 sg2 的第三个里程碑才不再造成伤害，那已经晚了好几个数量级。中间这段时间，这一层每一帧都在清空自己的供给。那款游戏 98 个自动化层级里有 52 个是这种行为。

after the repair修复之后
autoPrestige() {
  if (hasMilestone(this.layer, 2) &&
      hasMilestone("sg2", 3)) return true
}
resetsNothing() {
  if (hasMilestone("sg2", 3)) return true
}

Automation now arrives later, and that delay is the honest price of safety. Four rules encode the whole class: N-AUTOWIPE, N-MSDESTROY, N-POINTSWRITE and N-STATICMAX. They compare milestone sets, never their numbers. 自动化来得更晚了，而这段延迟就是安全要付的诚实代价。四条规则编码了这一整类问题：N-AUTOWIPE、N-MSDESTROY、N-POINTSWRITE 和 N-STATICMAX。它们比较的是里程碑集合，从不比较里程碑编号。

What survives a reset重置之后还剩什么

  • Milestones score on lifetime records. After the repair, 385 milestones read a career record and none reads a live counter. 里程碑判定基于生涯记录。修复之后，385 个里程碑读取的是生涯记录，没有任何一个读取实时计数器。
  • A layer with no doReset hook silently gets the engine's default keep list, which holds neither best nor total. That is the mechanism behind all three reports, and it applies to all 104 layers, not the one the player noticed. 一个没有 doReset 钩子的层级会静默拿到引擎的默认保留清单，而那份清单里既没有 best 也没有 total。这就是那三份报告背后的机制，而且它适用于全部 104 个层级，不只是玩家注意到的那一个。
  • Version numbers are compared as text by the engine, so a downgrade quietly rewrites every save it opens. 引擎把版本号当作文本来比较，所以一次降级会悄悄改写它打开的每一份存档。

Counters are not prizes计数器不是奖励

  • A static layer needs canBuyMax(). Without it the reset payout clamps to one floor, so each prestige banks exactly one and the entire upgrade ladder is unreachable. 静态层级需要 canBuyMax()。没有它，重置发放会被夹到一层，于是每次转生刚好只存下一个，整条升级阶梯都够不着。
  • A static layer's counter is its banked total, so trickling points into it earns less every second and hands back floors the next prestige cannot bank. 静态层级的计数器就是它存下的总量，所以把点数一点点滴进去，每秒收益越来越低，还会退回下一次转生存不下的零头。
  • Every currency award goes through the engine helper that writes lifetime records, because achievements and endgame conditions read those. 每一笔货币发放都走那个会写入生涯记录的引擎辅助函数，因为成就和终局条件读的就是它。

Why the old rules stayed quiet为什么旧规则保持沉默

  • Each part of the failure was reasonable on its own. 24 defects were repaired across 104 layers, 1,087 upgrades, 403 milestones and 8 challenges. 失败的每一部分单看都合理。24 个缺陷被修复，横跨 104 个层级、1,087 个升级、403 个里程碑和 8 个挑战。
  • After the repair the build reported 370 PASS, 36 WARN, 0 FAIL, every warning verified line by line. The player reports had all come in first. 修复后这个构建报告 370 PASS、36 WARN、0 FAIL，每条警告都逐行核实过。而玩家的报告早就先到了。
  • One report guessed that other layers shared the bug. All of them did, across 104 layers at once. The repair then checked every hook that existed, and confirmed it. 有一份报告猜其他层级也有同样的 bug。确实全都有，104 个层级一次中招。修复随后检查了每一个存在的钩子，并确认了这一点。

The checks that need a real build 那些需要真实构建才能做的检查

Three briefs passed all twenty-one design self-checks and were then overturned as soon as anyone measured the result. Paper reachability is a consistency argument, not a prediction. So the skill ships three tools that only have something to say once a build exists. 有三份简报通过了全部二十一项设计自检，却在任何人真正实测结果的那一刻被推翻。纸面可达性是一种一致性论证，不是预测。所以这项技能附带了三个工具，只有在构建存在之后它们才有话可说。

assets/harness/smoke.js
stage 5.5阶段 5.5

Loads the real mod files in Node against engine stubs and asserts them, so the first browser open is not the first test. It catches load-time throws, two layers sharing an id, broken startData contracts, and hooks that return NaN on a fresh save. It starts every layer unlocked on purpose, so a hook that only breaks once the layer is reachable fails here instead of in a player's console. 在 Node 里对着引擎桩加载真实 mod 文件并断言，让首次打开浏览器不再是第一道测试。它能抓住加载期抛错、两个层级共用一个 id、startData 契约损坏，以及在新存档上返回 NaN 的钩子。它刻意让每个层级一开始就解锁，所以一个只在层级可达后才出问题的钩子会在这里失败，而不是在玩家的控制台里。

node tools/smoke.js
assets/harness/simulate.js
stage 6阶段 6

Plays the build headlessly and reports the timeline. Shipped as a template rather than a finished instrument: its early timeline is trustworthy, and its total is not until you fit one point you already know from a real playthrough. The estimates above were wrong by a factor of four, by a factor of two thousand, and by enough that an entire multiplier architecture had to be replaced. The script says so out loud when a run finishes implausibly fast, because the alternative is a number nobody should quote. 无头游玩这个构建并汇报时间线。它以模板形式交付，而不是一件成品仪器：它的早期时间线可信，而总量在你用一个真实通关已知点校准之前并不可信。上面那些估算分别错了四倍、两千倍，还有一次错到整个倍率架构都得推倒重来。当一次运行快得不合常理时，脚本会直接说出来，因为另一个选项是一个谁都不该引用的数字。

node assets/harness/simulate.js <game-folder>
scripts/i18n_check.js
text layers文本层

Checks a text layer for missing keys, duplicate language codes, duplicate endonyms, and placeholder drift. One generated game ships 371 keys in three complete languages behind a phrase pool of 344 sentences, no two of them in the same language, which is a long way past what a bilingual toggle can express. With no js/lang/ folder the checker is a silent no-op. 检查一个文本层的缺失键、重复语言码、重复母语名和占位符漂移。有一款生成的游戏用三种完整语言交付了 371 个键，背后是 344 句话的短语池，没有任何两句属于同一种语言，这远远超出了双语开关能表达的范围。没有 js/lang/ 文件夹时，这个检查器是静默空操作。

node scripts/i18n_check.js <game-folder>
Everything learned the hard way ends up in one chapter: sixteen behaviours of the engine that its own documentation does not state. Among them, format() rendering every value below 1e-4 as 0.00, layeradd() silently ignoring a Decimal, a top-level throw in mod.js killing every initializer after it, and a buyable whose effect exponent equals its cost exponent funding its own next purchase until the economy detonates. Each entry was written after it cost somebody a debugging session, and each one names the build it came from. 所有吃过亏才学到的东西最后都归入一章：引擎有十六种它自己的文档从未说明的行为。其中包括 format() 把 1e-4 以下的每个值都渲染成 0.00、layeradd() 悄悄忽略 Decimal、mod.js 里一个顶层抛错会杀死它之后所有初始化器，以及一个效果指数等于成本指数的可购买项自己资助自己的下一次购买，直到经济爆炸。每一条都是在害某人花掉一整个调试会话之后写下来的，每一条都注明了它来自哪个构建。

What finished means here 在这里，完成意味着什么

A build ships when all of this holds. Every line of it comes from the corpus, from the engine author's own design notes, or from a defect that escaped an earlier game and is now a rule. 当以下全部成立时，一个构建才算可以交付。这里的每一条都来自语料库、来自引擎作者自己的设计笔记，或者来自一个从更早的游戏里逃出来、现在成了规则的缺陷。

Numbers数字

  • Requires ladders and cost curves taken from 329 measured games需求阶梯与成本曲线取自 329 款实测游戏
  • First prestige within minutes, endgame reachable, never instant首次转生在几分钟内，终局可达，绝不瞬达
  • Cost ladders spanning the measured six orders of magnitude or more成本阶梯跨越实测的六个数量级或更多
  • Self-scaling effects budgeted so a gain cannot compound past its own softcap自缩放效果有预算，使收益无法复利越过它自己的软上限
  • Pacing measured in the simulator rather than estimated on paper节奏在模拟器里实测，而非纸面估算

Content内容

  • The theme decides tree topology, currencies and hard caps, not just the labels主题决定树的拓扑、货币与硬性上限，而不只是标签
  • Effect-kind quotas keep layers from becoming walls of identical multipliers效果种类配额防止层级变成一堵堵相同的倍率墙
